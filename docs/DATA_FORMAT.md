# 数据格式与审计要求

UTF-8 CSV，英文表头，日期 ISO YYYY-MM-DD。价格为未复权实际合约价格，禁止将后复权连续合约当作成交合约。

## bars.csv

```csv
date,symbol,contract,open,high,low,close,volume
2024-01-02,RB,RB_EXAMPLE,100,102,99,101,200
```

上例纯示意，非市场价格。symbol 仅 RB/AU/CU/AG。每个 date+contract 唯一，合约归属固定；OHLC 正且高低价一致，volume 非负。输入按日期自动排序，重复直接拒绝。每个被选择合约需要足够的独立历史，TR 还需前收盘。不能将缺失交易日解释为零成交日。

## routes.csv

```csv
date,symbol,contract,known_on
2024-01-02,RB,RB_EXAMPLE,2024-01-01
```

date 是执行交易日，known_on 是该路由最迟已知日期，必须严格早于执行日；CSV 加载器拒绝同日或未来路由。仅日期校验不能验证数据真实的发布时间，仍需来源证明。直接调用 Engine.run 的 routes 字典视为已完成该审计，不含发布时间校验。

路由覆盖样本内所有输入品种的每个执行日；非目标合约历史也可同时输入。换月日必须同时有旧持仓合约和新目标行情。

## config.json

顶层 strategy 是 Config 字段；specs 以实际合约 ID 为键，每项字段为 multiplier、tick、margin_rate、fee_per_lot、close_today_fee_per_lot、slippage_ticks。可选 start/end 指定包含端点的交易区间；start 之前仅用于预热，不计收益。应额外载入 2023-01-01 之前的预热数据。

使用 scripts/make_synthetic.py 生成完整示例，不将虚构规格用于真实品种。正式研究必须显式提供已核验规格及本金。

## 当前加载器之外必须完成的审计

记录数据提供方、授权、版本、下载时间、时区、夜盘归属、交易日历、可用时间、修订记录、缺失和停板。当前引擎要求显式 calendar.csv，并按该日历检查品种/交易日覆盖及合约历史内部缺口。日历自身完整性仍需外部审计；不得从可能缺失的行情反推日历。

历史手续费/平今政策、保证金及合约规格的生效区间应另附表。发布数据及衍生结果前单独核实许可。

## calendar.csv（必需）

```csv
date
2024-01-02
2024-01-03
```

必须按日期严格递增、唯一、非空、规范 YYYY-MM-DD。含预热期及全部输入交易日；行情日期不得超出日历，每个日历交易日须有全部配置品种的行情。日历首尾必须覆盖显式 start/end 边界；若边界为非交易日，应由外部审计提供覆盖边界的日历及对应行情范围，不允许靠缺失输入缩短回测。执行区间无交易日则报错。

`Config.symbols` 默认四品种。显式子集实验示例：`Config(symbols=('RB',))`；JSON 对应 `"symbols": ["RB"]`。不允许空集合或重复品种，不接受配置外品种。不得将子集试验输出当作四品种组合结果。

金额和倍数必须有限且正，手数/窗口/预热/年化期数须为正整数，滑点须为非负整数。拒绝 NaN、Infinity、布尔数值、小数手数、重复或非规范日期。零成交量允许记录，但信号日不能形成共振。异常数据报错，不自行插值或补零。
